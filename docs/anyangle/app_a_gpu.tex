\section{Current GPU Footprint vs.\ Remaining CPU Kernels}

\texttt{MAGPARSER}'s Manhattan engine already offloads Morton sorting (\texttt{src/gpu\_morton.cu} using CUB/Thrust radix sort), R-tree spatial queries (\texttt{src/rtree.f90}), and RLE/PNUM merges (\texttt{src/RLEMerge.f90}, \texttt{src/gpu\_pnummerge.f90}) to NVIDIA GPUs via CUDA and OpenMP \texttt{target teams distribute parallel do}. In the any-angle stack, all exact integer predicates in \texttt{WideIntModule} and \texttt{TrapezoidModule} (\texttt{i128\_*}, \texttt{side\_at\_row}, \texttt{trap\_overlap\_positive}, \texttt{trap\_contact}) are already compiled with \texttt{!\$omp declare target} for device execution, while the five outer orchestration phases---\texttt{TrapSnapRound}, \texttt{TrapSweepUnion}, \texttt{TrapPNum}, \texttt{TrapTopo}, \texttt{TrapMorph}, and \texttt{TrapPred}---currently run on CPU OpenMP.

\subsection{Why Unified Memory (GB10) and \texttt{cudaMemPool\_t} Are Essential}
On NVIDIA Grace-Blackwell (GB10) systems with coherent NVLink-C2C unified memory, G1--G4 can share canonical \texttt{Trapezoid} arrays between CPU OpenMP and GPU CUDA kernels without explicit \texttt{cudaMemcpy} staging, provided that all intermediate allocations come from a persistent stream-ordered \texttt{cudaMemPool\_t} (Chapter~\ref{ch:memory}, Tier~3). Listing~\ref{lst:gpu_target} shows how \texttt{TrapezoidModule}'s existing \texttt{!\$omp declare target} predicates enable direct GPU pair evaluation in G4.

\begin{lstlisting}[caption={Direct OpenMP GPU target pair kernel pattern reusing \texttt{trapezoid.f90}'s \texttt{!\$omp declare target} \texttt{trap\_overlap\_positive}.},label={lst:gpu_target}]
!$omp target teams distribute parallel do &
!$omp   map(to: tA(1:nA), tB(1:nB), pair_a(1:npairs), pair_b(1:npairs)) &
!$omp   map(from: hit(1:npairs))
do k = 1, npairs
   hit(k) = trap_overlap_positive(tA(pair_a(k)), tB(pair_b(k)))
end do
!$omp end target teams distribute parallel do
\end{lstlisting}
