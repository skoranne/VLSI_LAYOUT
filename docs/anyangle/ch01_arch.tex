\section{Motivation: Beyond Manhattan Strip Approximation}

Classical VLSI physical verification engines---including \texttt{MAGPARSER}'s original Manhattan box engine---represent every mask layer as a set of axis-aligned rectangles (\texttt{Box} records of four coordinates $(x_1, y_1, x_2, y_2)$). For purely orthogonal designs, this representation is compact, cache-friendly, and admits $O(N \log N)$ scanline and R-tree algorithms. However, modern semiconductor manufacturing increasingly requires exact non-rectilinear geometry:
\begin{enumerate}
  \item \textbf{45-degree and arbitrary-angle routing} in RF/analog inductors, redistribution layers (RDL), and silicon photonics waveguides;
  \item \textbf{Curvilinear inverse lithography (ILT)} and multi-beam mask writer (MBMW) contours discretized into dense non-orthogonal polylines;
  \item \textbf{Rotational-invariance verification}, in which an entire hierarchical layout is rotated by arbitrary angles $\theta \in [0^\circ, 359^\circ]$ to stress-test geometric robustness, DRC rule consistency, and connectivity extraction without hidden axis-aligned bias.
\end{enumerate}

When a non-orthogonal polygon is fed into a Manhattan box engine, it must be rasterized into thin horizontal rectangular strips (controlled in \texttt{MAGPARSER}'s hierarchical box iterator by \texttt{LDB\_SLANT\_STRIPS}). This staircase approximation introduces three fatal pathologies:
\begin{itemize}
  \item \textbf{Perimeter inflation by $\sqrt{2}$:} A $45^\circ$ edge of Euclidean length $L$ becomes a Manhattan staircase of length $\sqrt{2}\,L$, destroying perimeter-dependent checks (\texttt{PERIMETER}, \texttt{COMPACTNESS}, resistance estimation).
  \item \textbf{Vertex and box explosion:} A single rotated wire spanning $10{,}000\text{ dbu}$ fragments into thousands of 1-dbu-tall strips, blowing up memory and sweep runtime.
  \item \textbf{Topological corruption:} Adjacent slanted shapes that touch along a shared diagonal edge acquire spurious gaps or overlaps at staircase corners, breaking \texttt{TOUCH}, \texttt{MEET}, \texttt{INSIDE}, \texttt{CONNECT}, and \texttt{GROW}/\texttt{SHRINK} morphology.
\end{itemize}

To eliminate these pathologies without sacrificing \texttt{MAGPARSER}'s Manhattan speed on orthogonal layers, the \textbf{any-angle engine} introduces a dual-representation \texttt{Layer} model and a complete, exact integer-lattice trapezoid geometry stack.

When a control file (\texttt{.ctr}) enables \texttt{var anyangle 1} (or the environment sets \texttt{MAGPARSER\_ANYANGLE=1}), \texttt{controlparser.f90} invokes \texttt{LoadAnyAngleLayers} immediately after opening the design database:
\begin{enumerate}
  \item For each layer, \texttt{db/layoutdb} invokes the exact hierarchical polygon iterator (\texttt{ldb\_polys\_load}), which applies all cell placement transforms (translations, mirrors, magnifications, and arbitrary-angle rotations) directly to polygon vertices without strip rasterization.
  \item An OpenMP parallel scan checks whether any edge has $\Delta x \ne 0 \land \Delta y \ne 0$ (\texttt{nslant > 0}). Purely orthogonal layers remain in Manhattan box storage unless \texttt{MAGPARSER\_FORCE\_TRAP=1} is active.
  \item Any layer with at least one slanted edge stores its raw unmerged polygons in \texttt{L\%raw\_off}, \texttt{L\%raw\_x}, \texttt{L\%raw\_y} (for single-pass joint snap rounding in subsequent two-layer Booleans!) and immediately runs \texttt{TrapMergePolygons} to populate \texttt{L\%traps(1:n\_traps)}.
\end{enumerate}

\begin{lstlisting}[caption={Exact slanted-layer detection and canonical merge in \texttt{src/anyangle\_ops.f90}.},label={lst:load_anyangle}]
!$omp parallel do reduction(+:nslant) private(i, j, jn, a, b)
do i = 1, npoly
   a = poff(i); b = poff(i + 1) - 1
   do j = a, b
      jn = j + 1; if (jn > b) jn = a
      if (px(jn) /= px(j) .and. py(jn) /= py(j)) nslant = nslant + 1
   end do
end do
!$omp end parallel do
if (nslant > 0 .or. AnyAngleForce()) then
   call store_raw(L, npoly, poff, px, py)
   call TrapMergePolygons(npoly, poff, px, py, traps, ntrap, mst, status)
   call store_traps(L, traps, ntrap)
end if
\end{lstlisting}

\section{Control-File Dispatch and Mixed-Operand Interoperability}

\texttt{MAGPARSER} parses \texttt{.ctr} scripts (optionally macro-expanded via \texttt{m4} and optimized by \texttt{TRSOptimizerModule}) in \texttt{src/controlparser.f90}. Whenever an operation touches an any-angle layer (or \texttt{AnyAngleForce()} is enabled, or a polygon-component predicate is invoked), \texttt{controlparser.f90} intercepts the operator and dispatches to \texttt{AnyAngleOpsModule}:
\begin{itemize}
  \item \textbf{Single- and Two-Layer Booleans:} \texttt{+}, \texttt{OR}, \texttt{OR2}, \texttt{*}, \texttt{AND}, \texttt{AND2}, \texttt{!}, \texttt{@}, \texttt{\~}, \texttt{NOT}, \texttt{FRAMENOT}, \texttt{\^}, \texttt{XOR}, and single-layer self-overlap \texttt{AND} (\texttt{TOP\_SELF2}). If one operand is Manhattan (boxes) and the other is any-angle (trapezoids), \texttt{layer\_polys} converts the box operand into 4-vertex polygons so both operands enter a single joint snap-rounding pass. If the Boolean result happens to be purely orthogonal (all vertical sides), \texttt{store\_traps} automatically downgrades it back into \texttt{Layer\%layer\_boxes} so all downstream Manhattan operations work seamlessly.
  \item \textbf{Morphology:} \texttt{GROW}, \texttt{SHRINK}, and signed \texttt{SIZE} (both isotropic scalar $d$ and anisotropic 4-directional $d_E, d_N, d_W, d_S$).
  \item \textbf{Polygon-Level Topologicals:} All 12 DE-9IM relations (\texttt{INTERACT}, \texttt{CUT}, \texttt{TOUCH}, \texttt{INSIDE}, \texttt{OUTSIDE}, \texttt{EQUAL}, \texttt{DISJOINT}, \texttt{MEET}, \texttt{OVERLAPS}, \texttt{COVERS}, \texttt{COVEREDBY}, \texttt{CONTAINS}) plus their \texttt{NOT\_*} and two-word \texttt{NOT <OP>} complements.
  \item \textbf{Polygon-Component Predicates:} All 20 rotation-invariant and orientation-specific predicates (\texttt{AREA}, \texttt{PERIMETER}, \texttt{VERTEX}, \texttt{HOLES}, \texttt{WIDTH}, \texttt{LENGTH}, \texttt{ASPECT\_RATIO}, \texttt{DIAMETER}, \texttt{COMPACTNESS}, \texttt{SOLIDITY}, \texttt{CONVEX\_CRITERIA}, \texttt{CONCAVE\_CRITERIA}, \texttt{IS\_RECTANGLE\_WITH\_ROTATION}, \texttt{IS\_SQUARE\_WITH\_ROTATION}, \texttt{NOTCH}, \texttt{ENCLOSE\_RECTANGLE}, \texttt{IS\_RECTILINEAR}, \texttt{IS\_45}, \texttt{IS\_RECTANGLE}, \texttt{IS\_SQUARE}) plus all \texttt{NOT\_*} complements and compound range constraints (\texttt{> a < b}).
  \item \textbf{FASCL Properties and Connectivity:} \texttt{PROPERTY:NAME = db:layer FASCL [...]} and \texttt{CONNECT} / \texttt{NET\_ID} evaluate transparently on any-angle trapezoid layers via \texttt{PropTableIndexPieces} and exact \texttt{trap\_overlap\_positive}.
\end{itemize}
