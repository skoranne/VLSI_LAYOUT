\section{From Canonical Trapezoids to OASIS \texttt{CTRAPEZOID} / \texttt{POLYGON}}

Although \texttt{MAGPARSER}'s internal representation stores canonical horizontal trapezoids whose sides are exact lattice lines, an individual trapezoid can have \emph{rational} (non-integer) $x$-coordinates at its top or bottom corners when a slab cut intersects a slanted boundary edge between two lattice vertices. SEMI P39 OASIS geometry records require \textbf{integer} vertex coordinates.

\texttt{src/db/trap\_out.cpp} solves this exact-export problem cleanly without rounding any coordinate:
\begin{enumerate}
  \item \textbf{Rational-Corner Classification:} For each trapezoid $i$, a 4-bit mask \texttt{rat[i]} tests whether each corner $(bl, br, tl, tr)$ has a non-zero modulo remainder in Eq.~(\ref{eq:side_x}) using \texttt{i128}.
  \item \textbf{Exact Pairing Across Rational Corners:} Every rational top corner on row $y_2$ of a trapezoid must match a unique rational bottom corner on row $y_1 = y_2$ of the trapezoid directly above it on the \emph{exact same lattice line}. Using a 64-bit hash of \texttt{(row, LineKey, side)} and parallel bucket sorting, \texttt{trapset\_run} pairs every rational corner one-to-one and unions the two trapezoids into a single export group.
  \item \textbf{Singleton Fast Path (\texttt{CTRAPEZOID} / \texttt{TRAPEZOID}):} Any trapezoid whose four corners are all integer lattice points (\texttt{rat[i] == 0}, forming a singleton group) is emitted directly to \texttt{oasis\_writer::Writer::trapezoid\_h} without polygon tracing:
  \begin{itemize}
    \item \textbf{\texttt{CTRAPEZOID} (record 26, types 0--23):} If both slanted sides have angles in $\{0^\circ, \pm 45^\circ, 90^\circ\}$ (all $45^\circ$-octagonal / $45^\circ$-rotated Manhattan shapes!), OASIS encodes the entire trapezoid in a compact \texttt{CTRAPEZOID} record specifying only a 5-bit type code plus width/height!
    \item \textbf{\texttt{TRAPEZOID\_A} (24), \texttt{TRAPEZOID\_B} (25), or \texttt{TRAPEZOID} (23):} If one or both sides have general rational slopes, OASIS emits a horizontal \texttt{TRAPEZOID} record with exact integer $\Delta a, \Delta b$ deltas.
  \end{itemize}
  \item \textbf{Multi-Trapezoid Group Path (\texttt{POLYGON}):} Any group joined across rational corners has all its outer boundary vertices on the integer lattice (Invariant I1). \texttt{GroupPoly::trace\_emit} extracts its exact lattice contour, bridges any holes via zero-width keyhole cuts inside a single trapezoid (guaranteed crossing-free), and emits an exact OASIS \texttt{POLYGON} (record 21).
\end{enumerate}

\section{FASCL Per-Polygon Properties and OASIS \texttt{PROPERTY} Support}

Modern verification and LVS/extraction flows attach rich typed metadata---such as electrical net IDs (\texttt{NET\_ID}), DEF net names (\texttt{NET\_NAME}), polygon area, perimeter, vertex count, and custom user-defined attributes---directly to individual polygons. \texttt{MAGPARSER} implements this via four tightly integrated modules:
\begin{itemize}
  \item \textbf{\texttt{PropertyTableModule} (\texttt{src/property\_table.f90}):} Stores per-polygon typed columns (\texttt{PK\_INT}, \texttt{PK\_FLOAT}, \texttt{PK\_STRING}, \texttt{PK\_STRUCT}) in flat SoA arrays indexed by canonical PNUM ordinal $1 \dots N_p$. On any-angle layers, \texttt{PropTableIndexPieces} binds the table directly to \texttt{TrapPNum}'s canonical ordinals and caches validity on the trapezoid-set hash.
  \item \textbf{\texttt{FASCLModule} (\texttt{src/fascl.f90}):} Compiles and evaluates CTR lambda expressions (\texttt{PROPERTY:NAME = db:layer FASCL [ (id) ... ] db:nothing}) in parallel over polygons, with exact \texttt{AREA}, \texttt{PERIMETER}, \texttt{VERTICES}, bbox, and \texttt{NET\_ID} builtins working on both Manhattan and any-angle layers.
  \item \textbf{\texttt{FASCLConnectModule} (\texttt{src/fascl\_connect.f90}):} Evaluates multi-layer connectivity (\texttt{CONNECT a cut b [cut c ...]}, built-in PDK stacks \texttt{SKY130}, \texttt{ASAP7}, \texttt{GT2N}) using exact \texttt{trap\_overlap\_positive} whenever any stack member is any-angle, assigning canonical \texttt{NET\_ID(id)} ordinals (verified byte-identical at \texttt{R000} and multiset-identical at \texttt{R030} across 186,565 nets on \texttt{SDT16S}).
  \item \textbf{\texttt{PropOasisModule} (\texttt{src/prop\_oasis.f90}) + \texttt{db/prop\_oasis\_writer.cpp}:} Serializes layers with their typed \texttt{PropertyTable} columns into standards-compliant SEMI P39 OASIS files (\texttt{exec oasout}).
\end{itemize}

\subsection{SEMI P39 \texttt{PROPERTY} Encoding, Repetitions, and \texttt{STRICT} Tables}

In \texttt{src/db/prop\_oasis\_writer.cpp}, each polygon element is followed immediately by its typed OASIS \texttt{PROPERTY} (record 28) records:
\begin{itemize}
  \item \texttt{PK\_INT} $\to$ OASIS value type 9 (signed integer);
  \item \texttt{PK\_FLOAT} $\to$ OASIS value type 7 (IEEE-754 64-bit double);
  \item \texttt{PK\_STRING} $\to$ \texttt{PROPSTRING} table reference (types 13/14/15 selected by character class: \texttt{n-string}, \texttt{a-string}, or \texttt{b-string});
  \item \texttt{PK\_STRUCT} $\to$ a single \texttt{PROPERTY} record whose value list alternates \texttt{[field-name (PROPSTRING ref), field-value, ...]}.
  \item \textbf{\texttt{PROPERTY\_REPEAT} (record 29):} Whenever consecutive elements share identical property records, the writer emits the 1-byte \texttt{PROPERTY\_REPEAT} record instead of re-encoding the payload.
  \item \textbf{Property-Aware Pattern Recognition \& Repetitions:} Polygons are grouped by the composite key \textbf{\texttt{(canonical shape, serialized property records)}} and decomposed into OASIS repetitions (type 1 2D grids, types 2/3 rows/columns, types 4/6/10 irregular point lists). Because SEMI P39 specifies that a \texttt{PROPERTY} record following a repeated geometry element applies to \emph{every} instance in the repetition, keying on both shape and properties guarantees that identical shapes with different \texttt{NET\_ID} or attribute values are never falsely merged.
  \item \textbf{\texttt{CBLOCK} and \texttt{STRICT} Mode:} Controlled via CTR \texttt{var oasis\_cblock}, \texttt{oasis\_repetition}, \texttt{oasis\_strict} (all default 1), and \texttt{oasis\_cblock\_bytes} (default 4 MiB). Cell bodies are deflate-compressed into \texttt{CBLOCK} (record 34) chunks aligned on record boundaries, and \texttt{STRICT} mode writes contiguous \texttt{CELLNAME}/\texttt{PROPNAME}/\texttt{PROPSTRING}/\texttt{LAYERNAME} tables with explicit offsets in the 256-byte-padded \texttt{END} record.
\end{itemize}

\begin{lstlisting}[style=cppstyle,caption={OASIS \texttt{PROPERTY} type mapping and property-keyed repetition invariant in \texttt{src/db/prop\_oasis\_writer.cpp}.},label={lst:prop_oasis}]
// Every element is followed by its PROPERTY records:
//   INT    -> signed integer (type 9)
//   FLOAT  -> IEEE double    (type 7)
//   STRING -> PROPSTRING ref (types 13/14/15 by character class)
//   STRUCT -> [field-name (PROPSTRING ref), field-value, ...]
// Identical consecutive property records emit PROPERTY-REPEAT (29).
// Pattern recognition groups polygons by (shape AND property records)
// so OASIS repetitions (types 1,2,3,4,6,10) never merge differing props.
\end{lstlisting}

\textbf{Any-Angle \texttt{exec oasout} Roadmap:} Currently \texttt{prop\_oasis.f90:132} rejects any-angle layers with a clean error message while Manhattan layers export full \texttt{PROPERTY} tables (verified by \texttt{db/regressions/fascl/run\_fascl\_regression.sh} against KLayout). Extending \texttt{exec oasout} to any-angle layers requires adding \texttt{fpo\_begin\_anyangle\_layer} in \texttt{db/prop\_oasis\_writer.cpp} to accept CSR lattice polygons (or \texttt{CTRAPEZOID} singletons) directly from \texttt{ldb\_trapset\_polys} grouped by PNUM ordinal, reusing the exact same \texttt{PROPERTY}, repetition, \texttt{CBLOCK}, and \texttt{STRICT} encoder.
